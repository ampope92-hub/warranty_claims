We reimburse our dealers for warranty work and I need a cost on every job in an audit batch before we set the reserve for it. /app/data/history.dat is the claims we have settled, with what we paid on each one. /app/data/batch.dat is the audit batch, same columns without the cost. There is a README next to them saying where each file came from and what the columns mean, worth reading before you start.

The claims team works in C so it has to live there. /app/model is a project with a stub at /app/model/src/main.c and a build script next to it. Fill the model in so that running bash /app/model/build.sh compiles it and writes /app/out/predictions.dat. Header line claim_id cost_gbp, then one line per claim in batch.dat, any order, whitespace separated same as the input. The cost is in pounds, it has to be finite and above zero, and dont hand back near enough the same number for every claim, these jobs differ by hundreds of pounds in labour alone, so the gap between your dearest and your cheapest quote in the batch has to come out above 100 pounds. Leave both files in /app/data exactly as we shipped them, thats what the auditor works from and we check it back against our copy.

The box is offline and there is nothing on it past the C standard library, so no fetching a stats package. It also has to work from a clean build: a fresh bash /app/model/build.sh with /app/out empty reads both files, fits, and writes the output itself. We run the same program over other audit batches in this format, so it needs to fit whatever is sitting in /app/data when it runs, and numbers worked out once and pasted into the source are no use to us. The auditor has the real costs and we'll score your quotes against them, plain R squared, and it has to reach 0.65. We put the same program over another audit batch you have not seen, same format, and it has to reach 0.50 there. The last model we were shown got 0.54 and looked completely healthy against the claims it was fitted to.
